# AN-01 主动通知与首页精修

状态：基线与架构文档已合并到 GitHub；首页与通知的修复源码候选已完成离线检查及独立评审，尚未部署、开启本人提醒或真实发送。公开范围与实际验收见 [verification.md](verification.md)。

## 用户目标

用户打开当前首页即可理解当前状态、最近一次实际结果、接下来的建议；同一 Agent 在网页与飞书共享记忆、方案、确认和回执。用户明确开启提醒后，收到重要事件与每日摘要。保留当前家庭能源世界和专业/历史入口，不另建首页或聊天系统。

## 已有能力和证据边界

- 已部署 Web/飞书共享 Service、SQLite、owner 与本机 site_1 首15分钟确认闭环。新增通知源码候选在原 monitor/串行业务执行器内增加有界 outbox tick；尚未切换正在运行的机器人。
- 原 messages/work 为入站恢复，进入 sending 后删除 work，不能直接复用为需要保留未知发送结果的主动 outbox。
- 当前 feed 仅 web/feishu、保留10分钟；不能用它补写全天记录。新 agent feed 只发表通知发送终态一次。
- 环境机独立只读接口候选已经离线验收。另一个获授权任务取得一次 HA 只读采样成功，看板登录超时；当前生产配置仍关闭，App 环境机路由尚未部署且返回404。采样不等于 App 已接通，不解除远端控制 gate。

## 本轮最小范围

1. 精修当前 ConsumerHome 的信息层次，让用户先看到状态与结果，再理解预计取舍与下一步；继续一套 composer、pending 与同帧数据，不把预计曲线当实际。
2. 在现 SQLite 增加 notification_settings 与 notification_outbox 两表；不引入队列平台、定时服务、独立时区表或新 Agent runtime。
3. 用户显式 master 开关。仅复用 bindings 已确认的家庭 IANA timezone；缺时区不可开启，返回 needsTimezone。默认每日20:00、静默22:00–08:00，不推断浏览器/设备时区。
4. 重要事件仅来自已持久 owner episode 事件、有效且新产生的可确认 pending、后续 reconcile 的新阶段；不增加 HA 轮询、价格推断或后台求解。首版 pending 范围为 memory/runtime_plan，clarify 与固定八小时样例不推送。
5. 通知仅信息提醒。用户回复请求安排后才走现 propose，再以新确认号执行；通知不覆盖 pending、不替用户保存偏好或同意设备控制。
6. 网页独立通知设置与最近20条状态，同步 agent 终态气泡；普通飞书即时回复不再生成重复主动消息。

## 不可缩减的边界

- 收件人只能来自同 app/site_1 唯一已绑定 owner 的 open_id，发送前重查；任何 API/LLM/用户文本不能指定收件人。
- 构造不发送。每次发送前先持久 UUID 与 sending；超时、5xx、部分失败或发送中崩溃为 unknown，不自动重发。
- 首次启用以 enabledAt 现实壁钟与当前 pending fingerprint 建基线，不补发旧事件；关闭取消未发送项，再启用不补发关闭期间积压。
- 单 episode/sequence 是事件去重单位，不存在全局 max(sequence)。事件扫描与每日摘要独立水位。
- 静默期延后合并；同 episode 保留最新核验状态。pending 发送前重查同引用/有效期，过期不复活、不延长。
- 无时区或无新事实不自动发。旧模拟设备时间/epoch 与户主现实通知日分开；费用只列同 episode 已核验15分钟，不称今日账单或节省。
- SDK accepted/sent 不表示户主已读；covered_by_reply 仅表明有过即时回复尝试。发送未知与设备执行未知分别展示。

## 首页验收目标

默认首屏可看见 Agent 输入和一个明确当前状态。当前实际/目标、最近已核验15分钟、未来预计安排、有效待确认项具有清晰标签；结果未知提供原 episode 的只读核对，不重新执行。无实际证据时不显示模拟成功/省钱数字。保留3D/二维保底、设备点选、专业/历史兼容、reduced motion、键盘焦点与移动端可达。

## 非目标

不启用持续自治 runner，不三站接管，不控制真实家庭或远端环境，不改变优化器/模型/安全边界，不后台自动生成方案、自动改偏好、推断低电量/电价告警或全天收益。不重做3D资产、影片/PPT或新页面平台。
