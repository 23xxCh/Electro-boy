# CH-03 飞书 Agent 最小闭环

状态：2026-10-17，root 已批准 S0 最小范围。复用 CH-02／RD／EW 的 Service、SQLite、单线程执行器、decision/feed 与本机 Debug1 core，不新增 Agent 平台、接口或客户端身份。

## 用户路径

已绑定用户在飞书私聊：问当前状态 → 告诉偏好或习惯 → 助手复述 → `记下 <当前资料号>` 持久保存。软件最低留电量候选可先同源预演；保存后生成新方案 → 展示首 15 分钟准确方向和功率 → `执行 <当前方案号>` → core 经官方 HA 下发、回读、结算 → 飞书答复与网页同 owner 投影同步。

状态、资料、帮助等常用短语直接进入已有只读工具，模型故障时仍可用；普通自然语言由既有真实模型做 JSON 意图及资料候选识别。大模型不能确认、指定设备实体、改优化器输出或声称真实家庭收益。习惯和活动仍可记忆、召回；当前只有无日期 `reserve_soc` 是 LP 硬约束，其他资料明确为讨论依据或缺项。

## 本轮最小修复

- 已绑定欢迎语不再要求重复绑定，不再把当前本机仿真错误说成仅历史回放。查询历史收益仍独立标来源。
- 常用状态／资料／计划短语直达原工具；明确、无日期的最低留电量百分比直达同一资料候选，不自动保存。
- 飞书结算答复可从同 episode 的只读 decision 补充实际功率和 SOC，只有匹配 episode、回读和结算完整且数值有限时展示；数据缺失保留已知阶段，不编数。
- 结果未知明确原 episode 查询命令；Worker 通用异常不得承诺“没有下发”，不得引导盲目重发控制。
- 非执行讨论明确可另生成本机预测方案，不再笼统声称已有本机预测和电价仍缺失；真实家庭未来输入仍未接入。
- “执行吧／确认”等无精确号只提示当前分离确认方式，不自动选 pending；替换、过期、其他 owner 或旧号不能执行。

## 验收与边界

离线临时 owner／临时 SQLite 从 normalize → Worker → Service 验只读信息、候选未保存、精确资料确认、重启保留、另号执行确认、同消息去重、旧 token／跨 owner 拒绝、unknown 原 ID 只读与网页同 owner feed。真实模型只允许无个人信息的独立探测，不保存本人资料。本轮不代替用户发飞书、不向本人发送测试、不写本人偏好、不替用户确认、不新增 HA 动作。现有 EW 官方 HA 物理收据仅只读复核，不为展示重执行。

reload 仅 root 核 Web／飞书／core idle 后操作；保留已配对机器人、DPAPI 与模型配置。完成时以现场源 hash、连接状态与独立检查区分“链已部署可用”和“真人已在飞书完成执行”；后者需真人入站，不能冒称。
